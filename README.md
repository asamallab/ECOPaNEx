## Key Event Retrieval Pipeline

A semantic retrieval system that maps toxicological observations cataloged in ECOTOX, and disease or phenotype annotations from CTD, to **AOP-Wiki Key Events (KEs)** using a range of embedding models and a TF-IDF baseline.

## Installation

The code was run with Python 3.13.11. To install the dependencies:

```bash
pip install -r requirements.txt
```

**Reproducibility note:** The reported results were generated with transformers 4.36.0 together with the other package versions listed in `requirements.txt`. The file specifies a transformers range compatible with sentence-transformers 5.3.0, so a fresh installation may use a newer transformers release. This should not materially change the embeddings, but scores may differ slightly. The files in `verified_predictions/` are the reference for the results reported in the manuscript.

## Verified Predictions

The `verified_predictions/` folder contains one tab-separated file per dataset (the ECOTOX file is gzip-compressed, see the note below):

| File | Dataset |
|------|---------|
| `CTD_disease_predictions_manually_verified.tsv` | CTD Disease |
| `CTD_phenotype_predictions_manually_verified.tsv` | CTD Phenotype |
| `ECOTOX_predictions_manually_verified.tsv.gz` | ECOTOX |

Each file contains the predicted KE mappings together with the result of manual verification in the column `Final_verdict`:

| Final_verdict | Meaning |
|---------------|---------|
| `Yes` | The predicted mapping is correct (the entry is mapped to the KE) |
| `No` | The predicted mapping is not correct |

**Note:** Because of GitHub's file size limit, the ECOTOX file is stored as a
gzip-compressed file (`ECOTOX_predictions_manually_verified.tsv.gz`). To
decompress it:

```bash
cd verified_predictions
gunzip -k ECOTOX_predictions_manually_verified.tsv.gz
```

The compressed file can also be read directly in Python with
`pd.read_csv("ECOTOX_predictions_manually_verified.tsv.gz", sep="\t")`.

## Pipeline Overview

```
Step 1  ->  Data Preprocessing
Step 2  ->  Data Retrieval (13 models)
Step 3  ->  Computing Metrics for Comparison
Step 4  ->  Label Randomization Baseline
Step 5  ->  Bootstrap Error Analysis (NDCG@10)
Step 6  ->  Statistical Testing (Friedman + Nemenyi)
Step 7  ->  Group A Union Pooling
Step 8  ->  Prediction for Unmapped Entries
```

The scripts are run from inside the `code/` folder, in the order of the step numbers.

---

## Pipeline

### Step 1 - Data Preprocessing

```bash
python3 1a_data_preprocessing.py <data_dir> <output_dir>
```

For example, from inside `code/`:

```bash
python3 1a_data_preprocessing.py ../input_data ../results/1a_data_preprocessing
```

- Loads and cleans AOP-Wiki KE entries, excluding KE IDs 294 and 1114
- For AOP-Wiki KE data, the code aggregates `title`, `process_name`, and `object_name` per KE into a single `ke_text` field
- For the other data files, the code
    - Filters each source file to rows already mapped (`Info == Mapped`)
    - Builds a query string per row for each source
    - Removes rows with invalid or out-of-range KE IDs

**Outputs** (saved to `output_dir`):

| File | Description |
|------|-------------|
| `aop_ke_cleaned.csv` | Cleaned KE corpus with `ke_text` |
| `ecotox_processed.csv` | Filtered ECOTOX rows with `query` column |
| `ctd_disease_processed.csv` | Filtered CTD Disease rows with `query` column |
| `ctd_phenotype_processed.csv` | Filtered CTD Phenotype rows with `query` column |

---

### Step 2 - Data Retrieval

Each model script follows the same interface:

```bash
python 2_<model>.py <base_dir> <input_dir> <output_dir>
```

**Models available:**

| Script | Model |
|--------|-------|
| `2_bge.py` | `BAAI/bge-large-en-v1.5` |
| `2_biobert.py` | `pritamdeka/BioBERT-mnli-snli-scinli-scitail-mednli-stsb` |
| `2_biolord.py` | `FremyCompany/BioLORD-2023` |
| `2_e5.py` | `intfloat/e5-large-v2` |
| `2_gte.py` | `thenlper/gte-large` |
| `2_instructor_xl.py` | `hkunlp/instructor-xl` |
| `2_jina.py` | `jinaai/jina-embeddings-v2-base-en` |
| `2_medembed.py` | `abhinand/MedEmbed-large-v0.1` |
| `2_minilm.py` | `sentence-transformers/multi-qa-MiniLM-L6-cos-v1` |
| `2_nomic.py` | `nomic-ai/nomic-embed-text-v1` |
| `2_pubmedbert.py` | `pritamdeka/PubMedBERT-mnli-snli-scinli-scitail-mednli-stsb` |
| `2_scibert.py` | `allenai/scibert_scivocab_uncased` |
| `2_tf_idf.py` | TF-IDF (bigrams, 50k features) |

**How retrieval works:**

1. Encodes KE corpus and queries using the chosen model
2. Computes cosine similarity between each query and all KEs
3. Ranks KEs by score and applies a similarity threshold of `0.5`
4. Rows where no prediction exceeds the threshold are marked as rejected

**Per-model outputs** (for each dataset × k value):

| File | Description |
|------|-------------|
| `<dataset>_k<k>_accepted.csv` | Queries with at least one prediction above threshold |
| `<dataset>_k<k>_rejected.csv` | Queries with no prediction above threshold |
| `<dataset>_metrics.csv` | Evaluation metrics for all k values |
| `all_metrics.csv` | Combined metrics across all datasets |

**K values evaluated:** `[1, 3, 5, 7, 10]`

### Step 4 - Label Randomization Baseline

Validates that model predictions carry genuine signal by comparing real performance against a randomly shuffled ground-truth baseline (k = 10).

```bash
python 4_ecotox_random_true_labels.py \
    <base_dir> <ecotox_ke_mapping_tsv> <output_dir> <ecotox_k10_accepted_file>

python 4_ctd_disease_random_true_labels.py \
    <base_dir> <ctd_disease_ke_mapping_tsv> <output_dir> <ctd_disease_k10_accepted_file>

python 4_ctd_phenotype_random_true_labels.py \
    <base_dir> <ctd_phenotype_ke_mapping_tsv> <output_dir> <ctd_phenotype_k10_accepted_file>
```

Each script produces a grouped bar chart comparing **Real** vs **Label Randomized** performance across MRR, NDCG@K, Hit@K, Precision@K, and Recall@K.

---

### Step 5 - Bootstrap Error Analysis (Per-Model NDCG@10)

```bash
python 5_error_analysis_ctd_dis.py
python 5_error_analysis_ctd_pheno.py
python 5_error_analysis_ecotox.py
```

For each dataset, these scripts:

1. Compute per-query NDCG@10 for every embedding model against ground-truth KEs
2. Run **1000 bootstrap subsampling iterations** (90% of queries per run) to estimate mean NDCG with 95% CI
3. Save per-model row-wise scores, bootstrap distributions, a combined summary CSV, and bar/box plots

**Outputs** (per dataset, e.g. `5_error_analysis_ctd_disease/`):

| File | Description |
|------|-------------|
| `<dataset>_<model>_rowwise_ndcg.csv` | Per-query NDCG scores for each model |
| `<dataset>_<model>_bootstrap.csv` | 1000 bootstrap mean NDCG values per model |
| `<dataset>_all_models_bootstrap_summary.csv` | Ranked summary: mean, std, 95% CI per model |
| `<dataset>_all_models_ndcg_barplot.png` | Bar chart of mean NDCG ± std, sorted best -> worst |
| `<dataset>_all_models_ndcg_boxplot.png` | Box plot of bootstrap NDCG distributions |

---

### Step 6 - Statistical Testing (Friedman + Nemenyi)

```bash
python 6_friedman_ctd_dis.py
python 6_friedman_ctd_phen.py
python 6_friedman_ecotox.py
```

For each dataset, these scripts:

1. Load bootstrap mean NDCG distributions (1000 runs) from Step 5
2. Run a **Friedman test** across all models to detect significant performance differences
3. If significant (p < 0.05), run **Nemenyi post-hoc pairwise comparisons** to identify statistically equivalent model groups
4. Assign models to groups using Union-Find over connected components (Group A = best-performing cluster, Group B = next best, etc.)

**Outputs** (per dataset, e.g. `6_friedman_test_ctd_dis/`):

| File | Description |
|------|-------------|
| `<dataset>_nemenyi_pvalues.csv` | Full pairwise Nemenyi p-value matrix |
| `<dataset>_nemenyi_sig_matrix.csv` | Pairwise significance matrix (SIG / no) |
| `<dataset>_friedman_groups.csv` | Group assignments per model with mean NDCG |
| `<dataset>_friedman_summary.csv` | Friedman χ², p-value, number of groups |
| `<dataset>_friedman_groups_barplot.png` | Colour-coded bar plot with group brackets |

---

### Step 7 - Group A Union Pooling

```bash
python 7_pooling_ctd_dis.py
python 7_pooling_ctd_phe.py
python 7_pooling_ecotox.py
```

For each dataset, these scripts:

1. Load Group A models (top statistical cluster from Step 6)
2. Take the **union of top-10 KE predictions** across all Group A models per query
3. Track how many Group A models agree on each predicted KE (model-agreement counts)
4. Save per-query union lists, KE frequency statistics, and distribution plots

**Outputs** (e.g. `6_friedman_test_ctd_dis/ctd_disease_groupA_union/`):

| File | Description |
|------|-------------|
| `<dataset>_groupA_union_list.csv` | Per-query union KE list and count |
| `<dataset>_groupA_union_dict.csv` | Per-query KE with model-agreement counts |
| `<dataset>_groupA_union_list.json` | JSON: query -> list of union KEs |
| `<dataset>_groupA_union_dict.json` | JSON: query -> KE -> number of agreeing models |
| `<dataset>_groupA_ke_global_frequency.csv` | Global KE frequency across all queries |
| `<dataset>_groupA_ke_frequency_intervals.png` | Bar chart: KE frequency distribution (binned) |
| `<dataset>_groupA_union_ke_count_distribution.png` | Bar chart: union KE count per query |

---

### Step 8 - Prediction for Unmapped Entries

```bash
python 8_prediction_ctd_disease.py
python 8_prediction_ctd_phenotype.py
python 8_prediction_ecotox.py
```

Applies the best-performing model to generate top-10 KE predictions for entries that have not yet been mapped (`Info = "to be predicted"`). No similarity threshold is applied - all top-10 predictions are returned regardless of score.

**How it works, for example in ctd_disease:**

1. Loads the input file (`input_data/CTD_Disease_KE_info.tsv`) and filters rows where `Info` is "to be predicted" (case-insensitive)
2. Loads the cleaned KE corpus (`aop_ke_cleaned.csv`) from Step 1
3. Encodes KE texts with the prefix `search_document:` and query disease names with `search_query:` using the Nomic model
4. Computes cosine similarity and returns the top-10 KE IDs and scores per query

The predictions are written to `results/8_prediction/` (the raw predictions, plus exploded and filtered versions).

## Evaluation Metrics

| Metric | Description |
|--------|-------------|
| **MRR** | Mean Reciprocal Rank - rewards ranking the correct KE higher |
| **NDCG@K** | Normalised Discounted Cumulative Gain at K |
| **Hit@K** | Fraction of queries with at least one correct KE in top K |
| **Precision@K** | Correct predictions / total predictions at K |
| **Recall@K** | Correct predictions / total ground-truth KEs |
| **Coverage** | Fraction of queries with any prediction above the similarity threshold |

---

## Notes

- Instructor-XL uses instruction-prefixed encoding for both corpus and queries; all other SentenceTransformer models use plain prefixes.
- Nomic uses asymmetric prefixes: `search_document:` for the KE corpus and `search_query:` for input queries; `trust_remote_code=True` is required.
- TF-IDF uses bigram features (`ngram_range=(1,2)`) with a 50,000-feature vocabulary and cosine similarity.
- Bootstrap analysis uses 1000 iterations with 90% subsampling and a fixed random seed (42) for reproducibility.
- Statistical grouping uses Union-Find over Nemenyi post-hoc connected components (p > 0.05 = same group).
